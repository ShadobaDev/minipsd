# minipsd — notes for coding agents

A header-only C99 library that writes and reads PSD files, plus a libvips plugin
(`libvips-plugin/`). Default branch: `master`.

How to contribute — tests, commit messages, the CHANGELOG — is in [CONTRIBUTING.md](CONTRIBUTING.md).
Read it before proposing a commit message or a CHANGELOG entry.

## Always
- The code compiles as C and as C++, without warnings, on every preset.
- A change to the bytes written comes with a test and is checked by an independent reader
  (`psd-tools`), not only by the project's own reader.
- A round trip keeps content, not another program's layout or out-of-spec bytes: see the *Round trip* rule under
  *What is read* in `docs/SPECIFICATION.md`. Never add an API field only to reproduce a quirk.
- Never claim what another program writes without a file saved by it (`tests/` fixtures).

## Build and test

One preset per toolchain (`msvc`, `mingw`, `linux-*`); commands in `docs/CHEATSHEET.md`.

- The psd-tools tests need a Python with `tests/requirements.txt`. Keep its venv in a lasting place
  (e.g. under `build/`): a venv in a temp folder gets half-cleaned and then fails on import. When
  psd-tools tests fail on import, check `Python3_EXECUTABLE` in the build's `CMakeCache.txt` first.
- A `mingw` build or ctest run that fails with no compiler message (the `consumer-*` tests among them)
  is an environment flake when run from PowerShell: rerun through bash with `C:\msys64\mingw64\bin` on
  `PATH` before suspecting the code. A failure that prints a compiler message is real.
